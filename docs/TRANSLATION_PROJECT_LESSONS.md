# 翻译项目复盘与避坑指南（DOCX/Excel）

## 1. 目标
沉淀本项目在“文档翻译 + 原格式回填”中的关键经验，避免后续项目把优化重点放错方向。

## 2. 核心结论（最重要的两条）

### 2.1 先定义问题维度：模型问题 vs 工程问题
在翻译链路里，必须先判断问题属于哪一层：

1. 模型问题：术语误译、语义偏差、风格不一致。
2. 工程问题：分段切分错误、占位符处理错误、回填破坏 run/样式、段落合并丢空格、标点粘连。

本项目的主要故障（粘词、占位符残留、格式异常）以工程问题为主，不是模型能力不足。  
如果一开始误判为模型问题，就会浪费时间在“换模型/调 prompt”，但无法解决回填后文档质量问题。

### 2.2 确定正确技术方案：按语义切分，不按固定长度切分
Excel 可以天然按单元格/行处理；DOCX 不能直接套用固定长度切分。  
DOCX 必须按语义边界切分（句子、段落、列表项、表格单元语义段），否则高概率出现：

1. 单词被截断后回拼，导致 `AnalyzerThe`、`withGB/T`、`93%below` 这类粘连。
2. 缩写和术语与前后词粘连（`WBC`、`RBC`、`USB` 等）。
3. 占位符错位或残留（`TKN_0`、`__ID_0__`）。

结论：先做“语义切分 + 稳定回填”再谈模型优化，收益最大。

## 3. 配套工程原则（支撑核心两条）

1. 回填优先级高于翻译速度：不破坏原文档样式、图片、分页、表格结构。
2. 占位符必须“冻结-翻译-还原”全流程闭环，且可审计。
3. 术语、品牌名、型号、标准号必须支持保护词机制（Do Not Translate）。
4. 质量检查用于“发现问题 + 提示重试”，默认不应无限制阻断下载。
5. `Retry Missing Segments` 必须只重试异常段，不能触发全量重跑。
6. Pause/Resume 必须是真断点续跑，不能回到起点。

## 4. 推荐处理流程（面向上线版本）

1. 上传文档后先做结构解析和语义切分。
2. 对品牌名/术语/占位符做预保护。
3. 分批翻译并立即局部回填。
4. 翻译完成后自动审计：源语言残留、占位符残留、粘词/空格异常。
5. 用户可点 `Retry Missing Segments` 重试异常段。
6. 提供 `Export Issue Report` 导出问题段清单。
7. 允许下载，但在有异常时给出明确风险提示。
8. 用户下载后可抽检关键页（封面、目录、表格页、图注页、术语密集页）。

## 5. 给后续项目的落地建议

1. 先做一份“问题分类表”（模型/工程）再排期。
2. 把“语义切分 + 回填稳定性”列为第一里程碑。
3. 测试样例必须覆盖：长文档、表格、编号列表、混合中英、占位符、缩写密集页。
4. 验收标准要包含“可发布文档质量”，不仅是“翻译完成率”。

---

这份文档用于约束后续同类项目的技术路线：  
先把问题定义清楚，再用正确切分方案实现稳定回填，最后再做模型层优化。
