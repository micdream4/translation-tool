# 术语资产清单

> 定位：本工具除了保结构、做质检，还要成为 **POCT 专业翻译的固定译法库**。专用词汇和固定表达需要有一份可审核、可持续补充的权威来源。本文记录现状，方便后续补全。
> 清单基于 v0.2.1 的代码和资源文件整理。

- 来源领域：报告 56 条、说明书 42 条、通用 12 条。
- 类型：检验项目 24、病理 21、章节标题 18、法规 6、质量 6、质控 5、短语 5、界面文案 5、标识标签 4、接口 4，其余为设备、安全、药理、质控物等。

## 二、缺口

1. **110 条全部是草稿。** `status` 列全部为 `draft_for_review`，没有任何一条经过审核。目前草稿词和已审核词在程序里没有区别，都会被强制使用。
2. **语言没覆盖全。** 工具支持 12 个目标语言，种子表只有 8 列。缺：**繁體中文（台灣）、波兰语、罗马尼亚语**。（简体中文是源语言，不需要。）
3. **两套术语表不同步。** 代码内英文术语表 79 条和 CSV 种子 110 条内容有重叠，但分开维护，同一个词在两处可能写法不同。
4. **只能改文件，没有页面入口。** 增删术语要改 CSV、重新生成、提交、部署。
5. **翻译记忆不共享。** 每个人的浏览器各存一份，团队里同一个原文可能得到不同译法。
6. **没有"术语使用情况"报告。** 质量报告里没有一项告诉你"这份译文里哪些固定术语被用了、哪些原文命中了术语但译文没用"。
7. **缺少表达层面的固定译法。** 现有条目偏单词和短语。说明书里反复出现的固定句式（警告语、操作步骤、储存条件、免责声明）还没有成体系的收录。

## 三、你补充时可以怎么给我

直接给 Excel 或 CSV 即可，我来整理入库。建议至少带这些信息：

| 列 | 说明 | 必填 |
|---|---|---|
| `zh_source` | 中文原文（词或固定句式） | 是 |
| 各语言译文 | 已确认的固定译法，哪种语言有就填哪种 | 是（至少一种） |
| `term_type` | 类型，比如检验项目、病理、界面文案、警告语、操作步骤、储存条件 | 建议 |
| `status` | `approved` 表示已审核 | 建议 |
| `notes` | 使用场景、不能这样翻的反例、为什么 | 建议 |
| `source_files` | 出自哪份说明书的哪一章 | 建议 |

模板见 `docs/templates/glossary-template.csv` 和 `docs/templates/do-not-translate-template.csv`（里面各有一行示例，使用前请删除）。

另外有三点请你在补充时一并告诉我：
1. **哪些词必须固定**（强制替换），哪些只是推荐（给模型参考）。
2. **同一个中文在不同语境下译法不同**的，请标出语境，比如"检测"在标题和在动作里。
3. **不同语言有不同审核人**的话，每种语言各自标记是否已审核。
